## 100 / 10,000条存档对照

每组独立浏览器，重复进入/输入5次，观察滚动帧；Chromium另检查15次重复进入后的回收内存变化。WebKit直接大事务造数耗时很长，夹具改为每批250条；两版使用相同方式，计时不包含造数及初始水合。原始结果见 [性能记录](../public-selected-performance-2026-10-24.json)。

| 内核 / 记录数 | 进入中位：1.1.1 → 1.2 | 输入中位：1.1.1 → 1.2 | 渲染消息数 |
| --- | --- | --- | --- |
| Chromium / 100 | 56.7 → 53.5 ms | 14.3 → 14.3 ms | 50 / 50 |
| Chromium / 10,000 | 143.9 → 131.2 ms | 14.2 → 13.0 ms | 50 / 50 |
| WebKit / 100 | 172.9 → 178.6 ms | 62.7 → 49.2 ms | 50 / 50 |
| WebKit / 10,000 | 262.8 → 252.4 ms | 28.2 → 32.7 ms | 50 / 50 |

未出现脚本设定的明显回退（进入超出2倍且500ms、输入超出2倍且150ms）或丢失分页。该结果是本机合成样本；仍有单次进入及长任务波动，不能当作真实手机、媒体大档、冷启动、长期使用或所有模型组合的性能保证。
